# 工作流

## 目的

该目录描述用于计划、执行、评审和发布协调的可重复 AI 工厂工作流。

## 单一事实来源

注册表描述未来工作流声明，状态描述工作流进度模型，模板描述可复用工作流文档。

## 已声明工作流

- [想法到产品理解](idea-to-product-understanding.md)：将原始想法整理为可确认的产品理解草案。
- [需求点记录](requirement-capture.md)：将已确认产品理解拆成需求点记录。
- [PRD 草案](prd-draft.md)：将已确认需求点记录整理为可审阅 PRD 草案。
- [Design Brief 草案](design-brief-draft.md)：将已确认 PRD 转成可审阅设计输入。
- [UI 设计图草案](ui-design-draft.md)：将已确认 design brief 转成可审阅 UI 设计图。
- [规格到实施计划](spec-to-implementation-plan.md)：手动优先地把明确给定的规格转换为可审阅实施计划。
- [UI 图到代码实现](ui-to-code-implementation.md)：将已确认 UI 图、设计系统和工程边界转换为可验证前端实现。
- [组件库维护](component-library-maintenance.md)：维护 Figma、设计系统、shared-ui 和页面消费之间的组件一致性。

## 边界

第一阶段中，工作流记录不是可执行注册表。运行时系统不得从该目录树自动发现工作流。

## 流程实例边界

工作流实例按目标连续性划分，不按对话次数划分。

当用户围绕同一个目标持续补充、修正、评审需求或调试设计图时，应更新同一个 workflow run 的状态轨迹、人工确认点和 revision 记录。不要因为发生了新一轮对话就创建新的主流程。

只有目标改变、范围结构性扩大、产生独立子方向，或已关闭流程需要重新启动时，才创建新的 workflow run 或子流程。子流程必须显式链接回原流程。

## 演进

只有所有者、触发器、状态、记忆领域和失败处理都明确后，才推动工作流自动化。
