# 功能开发 Playbook

## 适用场景

用于 Phase 2 之后的受控产品功能开发。Phase 1.1 不使用该 playbook 开发正式产品功能。

## 禁止场景

- 没有 PRD。
- 没有 design brief 或 UI 设计资产。
- 没有工程规格。
- 没有验收标准。
- 需求仍处于 `needs-confirmation`。

## 输入

- 已确认 PRD。
- 已确认工程规格。
- 关联需求点记录。
- 设计 brief 或 UI 设计图。
- 验证要求。

## 步骤

1. 确认阶段门禁允许进入功能开发。
2. 检查需求、设计、契约和工程规格是否互相可追溯。
3. 生成或读取实施计划。
4. 按 contract-first 顺序处理跨边界变更。
5. 实现最小可验证变更。
6. 运行验证命令。
7. 进行 review。
8. 记录阶段结果和 memory 候选。

## 检查清单

- 是否有关联 PRD。
- 是否有关联 design brief。
- 是否有明确非目标。
- 是否未绕过 SDK。
- 是否未让前端承担业务编排。
- 是否有测试或人工验收方式。
- 是否更新 Obsidian 和飞书展示材料。

## 产出

- 实现变更。
- 验证结果。
- Review 记录。
- 记忆更新建议。
- 阶段成果记录。
