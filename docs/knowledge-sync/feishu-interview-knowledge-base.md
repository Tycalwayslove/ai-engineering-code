# 飞书面试展示知识库方案

## 定位

飞书知识库不是 Obsidian 的镜像，而是面向面试官和外部读者的项目展示入口。

它应该回答三个问题：

- 这个项目和普通 Web 应用有什么不同？
- 你在其中做了哪些系统性工程决策？
- 这些决策如何通过代码、契约、文档和工作流留下证据？

## 页面结构

| 页面                    | 作用                     | 读者收获                  |
| ----------------------- | ------------------------ | ------------------------- |
| 00 项目首页             | 快速建立项目印象         | 一分钟理解项目定位和亮点  |
| 01 项目背景与目标       | 解释为什么做这个项目     | 理解问题意识和产品判断    |
| 02 架构总览             | 展示系统分层和边界       | 理解技术选型和演进路径    |
| 03 阶段演进记录         | 记录从骨架到薄切片的过程 | 看到真实推进路径          |
| 04 核心技术亮点         | 提炼面试可讲的差异点     | 快速定位可追问话题        |
| 05 工作流与 AI 协作体系 | 说明 AI 原生协作方式     | 理解人机协同不是口号      |
| 06 面试讲解稿           | 给候选人准备讲述路径     | 形成 3 分钟和 10 分钟版本 |

## 同步原则

- 不同步全部过程细节，只同步已经沉淀出的成果。
- 每个页面都要包含“做了什么、为什么这样做、下一步怎么演进”。
- 关键结论必须能回到仓库、契约、规格或提交记录中找到证据。
- 飞书内容面向读者，Obsidian 内容面向自己，仓库内容面向协作。

## 后续维护

- 每个阶段完成后，先写 Obsidian 阶段记录。
- 再从阶段记录中提炼一段可公开展示的飞书更新。
- 如果涉及架构方向变化，同步更新 ADR、规格或约定文档。
