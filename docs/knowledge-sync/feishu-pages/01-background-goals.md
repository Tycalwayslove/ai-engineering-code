# 01 项目背景与目标

## 背景

AI 辅助开发已经不只是“让模型写代码”。当一个项目长期运行后，真正困难的是让 AI 持续理解同一个系统：知道当前架构为什么存在，知道哪些目录是权威来源，知道哪些能力只是计划中，知道哪些边界不能随便打破。

如果没有稳定结构，AI 很容易重复制造以下问题：

- 把提示词、规格和记忆混在一起。
- 在前端写业务编排和状态机。
- 过早拆分微服务。
- 重复定义接口契约。
- 忽略历史架构决策。
- 把一次性脚本伪装成长期基础设施。

## 项目目标

本项目希望构建一个 AI 原生软件工厂基础架构，让人和 AI 都能在同一个可读、可查、可演进的系统里工作。

核心目标包括：

- 建立稳定的 monorepo 结构。
- 同时支持 TypeScript 前端生态和 Python AI 后端生态。
- 把规格、记忆、提示词、工作流和设计系统作为一等目录。
- 使用契约层稳定前后端、工作流和记忆系统之间的协议。
- 保持早期运行时足够轻，不引入无压力的复杂基础设施。
- 为后续 AI workflow、memory、RAG、agent runtime 预留清晰演进路径。

## 非目标

当前阶段不追求：

- 生产级分布式系统。
- Kubernetes 或服务网格。
- 自动执行 agent 循环。
- 提前接入 LangGraph。
- 提前建设向量数据库。
- 把所有服务边界立刻变成独立部署单元。

这些能力只有在真实工作流、状态管理、审计和协作压力出现后才会进入实现。

## 当前判断

项目选择“Thin Polyglot Skeleton”路线：从第一天就承认 TypeScript 和 Python 的不同职责，但先保持运行时集中、边界清晰、实现简单。

这让项目既能长期承载 AI 工程复杂度，又不会在早期被基础设施拖慢。
